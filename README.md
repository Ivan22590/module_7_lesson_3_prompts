# План питья воды на рабочий день

## Инструкция по шагам

1. 09:00 — стакан воды сразу после начала работы
2. 10:00 — стакан воды перед первой паузой
3. 11:00 — стакан воды после утренних задач
4. 12:00 — стакан воды за 10 минут до обеда
5. 13:30 — стакан воды после обеда
6. 15:00 — стакан воды во время дневного перерыва
7. 16:30 — стакан воды перед завершением основных задач
8. 17:30 — стакан воды перед окончанием рабочего дня

## Заметки

- Пейте воду медленно, чтобы лучше усваивалась
- Используйте напоминания на телефоне для регулярности
- Держите бутылку воды на рабочем столе всегда

---

## Цель исследования

Собрать управляемый промпт по схеме роль → контекст → задача → формат ответа, получить стабильный структурированный ответ модели и превратить его в полезный артефакт. Отдельно проверить, даёт ли одна итерация качества (уточнение роли + few-shot пример) измеримо лучший результат при неизменных параметрах генерации.

---

## Ход исследования

1. Выбрана бытовая мини-задача: план напоминаний пить воду в течение рабочего дня (9:00–18:00, минимум 8 стаканов).
2. Собран базовый промпт (запуск 1): роль — «персональный помощник по полезным привычкам», контекст — рабочий день и цель по объёму воды, задача — составить расписание, формат — строгий JSON {title, steps, notes}.
3. Запуск выполнен через модуль llm (LLMClient.chat): модель openai/gpt-4.1-mini, temperature 0.2, системная инструкция отправлена отдельным сообщением с ролью system.
4. Модель по умолчанию (openai/gpt-6-luna) отвергла temperature 0.2 с ошибкой HTTP 400 — выбрана openai/gpt-4.1-mini, которая поддерживает этот параметр.
5. Сделана одна итерация качества (запуск 2): роль уточнена до «UX-исследователя привычек», добавлены ограничения (шаги измеримые и с привязкой ко времени, заметки до 12 слов, ответ без markdown-обёрток) и добавлен few-shot пример готового JSON.
6. Повторный запуск выполнен с теми же моделью и temperature, чтобы сравнение было корректным — менялся только текст промпта.
7. Все запросы, ответы и параметры сохранены в prompt_experiment_results.json; JSON извлекается из ответа с очисткой от markdown-обёртки.
8. Ответы сравнены по трём критериям: соответствие JSON-формату, полезность шагов (steps), лаконичность заметок (notes).
9. Итоговый артефакт — этот README: инструкция собрана из лучшего ответа.
